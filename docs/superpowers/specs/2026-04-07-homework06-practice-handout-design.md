## 1. 目标

创建一个新的 `homework06.qmd`，帮助学生复习并练习第六讲的核心内容：

1. 多元线性回归中“控制其他变量不变”的系数解释。
2. 模型作用范围、研究问题与嵌套模型比较之间的联系。
3. 整体 F 检验、部分 F 检验与单个变量检验的区别和统一视角。
4. `R^2`、调整 `R^2`、部分 `R^2` 与新增解释力的理解。
5. 多重共线性的诊断及其对解释和检验的影响。

讲义应延续现有作业风格，但更强调“短回顾 + 立即练习”的复习节奏。

---

## 2. 设计原则

### 2.1 结构原则

- 采用 **4 个 question parts**，避免题目过碎。
- 每个 part 开头先给出一段**简洁的关键知识回顾**，只覆盖后续小问需要用到的内容。
- 每个 part 以 **应用型 R 分析** 为主，搭配少量统计解释题。
- 全文使用同一组示例数据与相近模型，减少不必要的数据准备负担。

### 2.2 内容原则

- 与 `talk06.qmd` 保持术语和逻辑顺序一致。
- 练习重点放在“解释、比较、判断”，而不是大量机械计算。
- 参考答案通过 `show_solutions` 参数控制，避免额外维护独立答案文件。

### 2.3 风格原则

- 语言使用中文。
- 数学表达使用 LaTeX。
- R 代码使用 tidyverse 风格，必要时保留 `lm()`、`anova()`、`drop1()`、`vif()`、`kappa()` 等基础函数。

## 4. 题目设计

### 4.1 Part 1：系数解释与模型作用范围

**回顾重点：**

- 多元回归系数表示“在其他解释变量保持不变时”的条件平均变化。
- 同一个变量在不同模型作用范围下，回答的是不同研究问题。

**练习目标：**

- 拟合一元与多元模型并比较同一变量系数的含义。
- 用规范语言写出多元回归系数解释。
- 识别“模型作用范围改变，结论含义也会改变”这一点。

**题目形式：**

- 给出 `mtcars` 数据准备和两个或三个嵌套模型。
- 让学生比较 `hp` 在不同模型中的系数含义。
- 要求学生写出一段规范解释，并指出错误表述为何不严谨。

### 4.2 Part 2：研究问题、嵌套模型与 F 检验

**回顾重点：**

- 整体 F 检验、部分 F 检验和单个变量检验都可以看作简化模型与完整模型的比较。
- 写假设前要先明确研究问题、简化模型和完整模型。

**练习目标：**

- 把文字研究问题翻译成原假设和备择假设。
- 区分整体 F 检验与部分 F 检验在问题表述上的差异。
- 使用 `anova()` 与 `drop1()` 支持结论。

**题目形式：**

- 给出 2-3 个研究问题描述。
- 让学生写出每个问题对应的 reduced/full model。
- 运行并解释 `anova()` 或 `drop1()` 的结果。

### 4.3 Part 3：拟合优度与新增解释力

**回顾重点：**

- `R^2` 衡量完整模型解释总变异的比例。
- 调整 `R^2` 在比较不同复杂度模型时更有意义。
- 部分 `R^2` 描述新增变量对剩余变异的额外解释比例。

**练习目标：**

- 提取并比较 `R^2` 与调整 `R^2`。
- 根据嵌套模型计算一个变量组的部分 `R^2`。
- 解释“高 `R^2`”与“新增变量是否仍有贡献”并不是同一个问题。

**题目形式：**

- 给出 reduced/full model。
- 让学生计算并解释多个拟合优度指标。
- 要求学生用文字比较这些指标各自回答什么问题。

### 4.4 Part 4：多重共线性诊断与解释

**回顾重点：**

- 多重共线性不会必然让整体模型失效，但会让单个系数更不稳定。
- 常见诊断包括散点矩阵、相关矩阵、VIF 和条件数。

**练习目标：**

- 检查 `hp`、`wt`、`disp` 之间的相关关系。
- 使用 `vif()` 和 `kappa()` 诊断共线性。
- 解释为什么“整体显著、单个变量不稳定”可能同时出现。

**题目形式：**

- 先做图和计算诊断量。
- 再让学生写出统计解释。
- 最后加入一个简短追问：若目标是解释单个系数，应如何面对较强共线性。

## 5. 参考答案设计

`homework06.qmd` 使用参数化方式控制答案显示：

```yaml
params:
  show_solutions: false
```

每个 part 的答案都放在：

```markdown
::: {.content-visible when-meta="show_solutions"}
**Solution:** ...
:::
```

答案设计要求：

- 给出可运行的 R 代码。
- 给出简洁、规范的统计解释。
- 不写成长篇讲义式说明，只保留学生核对所需的关键步骤和结论。

## 6. 数据流与实现约束

### 6.1 数据选择

- 优先使用 `mtcars`，与讲义示例保持一致。
- 如无必要，不引入新数据集。

### 6.2 代码组织

- 公共数据准备放在前面统一完成。
- 每个 part 在此基础上延续分析，避免重复清洗代码。
- 保持代码块数量适中，避免作业文件过长。

### 6.3 可渲染性

- 目标输出为 HTML。
- 代码必须可以直接渲染，不依赖课外资源文件。
- 数学公式、代码、文字说明都应在一个文件中自洽。

## 7. 验收标准

完成后的 `homework06.qmd` 应满足：

1. 有 **4 个 part**。
2. 每个 part 都先有简洁回顾，再进入练习。
3. 练习内容覆盖 `talk06.qmd` 的主要主题。
4. 作业以 applied R analysis 为主，但保留必要统计解释题。
5. 使用 `show_solutions` 参数包裹答案。
6. 文件风格与 `homework05.qmd` 协调一致，并可成功渲染为 HTML。

---

## 8. 风险与取舍

- 若每个 part 小问过多，作业会变成长报告，因此应控制在“一个主问题 + 若干紧密相关小问”的粒度。
- 若只强调代码，不要求统计语言表达，就无法检验学生是否真正理解“控制其他变量不变”等核心概念。
- 若引入太多新函数或新数据，会把复习题变成探索题，不符合本次讲义目标。
